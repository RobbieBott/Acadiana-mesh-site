# Repeater directory backend (PocketBase)

Serves **data.acadianamesh.com**, which the website's `/repeaters/` and `/repeaters/manage/` pages read and write.
Jekyll ignores this folder (`exclude` in `_config.yml`). Nothing here is secret.

- `Dockerfile`: PocketBase 0.40.6, checksum-verified, with the migrations baked in.
- `pb_migrations/1795600000_repeater_directory.js`: collections and access rules.
  - `users`: name, callsign, role (`user`/`admin`). Sign in by emailed code or password. Only admins add people; there is no public sign-up.
  - The Site Owner changes roles in **Manage → Permissions**. Admins may invite regular users and edit directory profiles. The Site Owner can change another person’s sign-in email from **People**. Changing an email resets credentials and requires verification at the new address.
  - `repeaters`: every column of the old Google Sheet, plus owner, contact details, "show publicly" switches and `managers`. Admins edit all; users edit repeaters where they are a manager and can't change managers. Permanent account, repeater, and observer listing deletion requires the Site Owner. The owner name is required on every save.
  - `repeaters_public`: public read-only view. Email, phone and Discord appear only when the owner ticked "Show publicly".
  - `prefixes`: reserved prefixes. Anyone can reserve (name, email, what it's for); signed-in users see, rename and release their own (matched by account or reservation email); admins see and edit all. Public reads go through the `prefixes_public` view (code, label, created).
  - `maintenance`: repairs log (public; admins and the repeater's managers write).
- `pb_migrations/1795600100_import_sheet.js`: one-time import of the sheet (17 repeaters, 14 reserved prefixes), exported 2026-11-19.
- `pb_hooks/profile_contact.pb.js` + `profile_contact.js`, migration 1795601500: "Use my profile" — `repeaters.contact_from` (relation to users) makes the repeater's owner name/callsign/email/phone/Discord copy that account's profile (users gained optional `phone`, `discord`); saving a profile updates every repeater that follows it. People can link only to their own profile (admins to anyone's); the public ticks stay per repeater.
- `pb_hooks/prefixes.pb.js`: on reserve, uppercases the code and refuses anything that isn't exactly 4 or 6 hex characters or that starts with 00 or FF (MeshCore's "reserved id hashes", `examples/simple_repeater/main.cpp`), overlaps another reservation (admins may overlap old 1-byte ones), matches a directory repeater's key or prefix, or matches a repeater the analyzer hears (skipped if the analyzer is down). Non-admins: max 5 per email; signed-in users always reserve under their own account and email. Emails a confirmation. Rate limit `prefixes:create` 5 per 10 minutes per IP. The field pattern enforces the same format.
- `pb_hooks/corescope_sync.js` + `corescope_sync.pb.js`: every hour (minute 17) and from the admin "Sync from CoreScope" button (`POST /api/directory/sync`), adds repeaters whose advertised location is inside the **us-la-lft** boundary (`pb_hooks/lft_boundary.js`, copied from `assets/data/la-regions.json`; no location → skipped), and removes earlier auto-added entries that are outside it as long as nobody touched them (no owner, managers, claims or maintenance). Also runs once at startup. CoreScope's own `region_placement` "LFT" is not used — it includes anything our observers hear. New entries get name, key, 1/2/3-byte prefixes, path hash size, status Online, `source = corescope` and no owner. It never overwrites entered data, except that an entry whose key the mesh doesn't hear adopts the mesh key of the single repeater matching its reserved 2-byte prefix or name. Deleting a repeater adds its key to `sync_ignore` so the sync won't add it back (remove it there to allow it again). Analyzer URL: `ANALYZER_URL` env, default https://analyzer.acadianamesh.com.
- `pb_hooks/claims.js` + `claims.pb.js` and migration `1795600600_claims.js`: "Claim this repeater" on the public page creates a `claims` row (anyone; always `pending`; max 3 per IP per 10 min; one pending claim per email per repeater) and emails verified admins. Admins approve on the manage page's Claims tab (`POST /api/directory/claims/{id}/approve`): creates the user if needed (random password, invite = set-your-password email), adds them to `managers`, fills an empty owner name/callsign, marks the claim approved. Decline just marks it declined. A claim grants nothing until approved.
- `pb_hooks/message_owner.pb.js` + migration `1795600900_message_owner.js`: owners' emails are never public. `repeaters_public` has `can_message` instead of `email`; "Message the owner" posts to `POST /api/directory/message` (no sign-in; 3 per IP per 10 min; honeypot `website`; name/email stripped of line breaks), which emails the owner's `contact_email` with `Reply-To` = the visitor. Nothing is stored. Phone/Discord still show when "Show publicly" is ticked.
- `pb_migrations/1795600200_settings.js`: app name/URL, sender info@acadianamesh.com, rate limits, proxy header, nightly backups (7 kept).

## On the droplet

- Code: `/root/acadiana-stack/pocketbase/` (copy of this folder). Data: `/root/acadiana-stack/pocketbase/pb_data/`.
- Encryption key: `/root/acadiana-stack/pocketbase.env` (chmod 600).
- Compose service: `compose-service.yml`. Caddy block: `Caddyfile-block`.
- Dashboard: **not public** (Caddy returns 404 for `/_/` and the superuser/settings/backups/logs APIs). Open an SSH tunnel to the droplet — `ssh -L 8090:127.0.0.1:8090 root@134.122.27.51` — then browse to http://localhost:8090/_/. Sign-in is password + a one-time code emailed to the superuser (MFA, migration 1795601100). SMTP login goes in Settings → Mail.
- Locked out of the dashboard (lost password or email)? On the droplet: `docker exec pocketbase /pb/pocketbase superuser upsert you@example.com 'new-password' --dir=/pb/pb_data` (the emailed code is still required).
- Invites (People tab, claim approval) send the set-your-password email: its #reset=… link on acadianamesh.com/repeaters/manage/ sets a password, confirms the email and signs the person in. Old #verify=… links still confirm the email and offer a password link. Email matching ignores capitals (`users` email index is COLLATE NOCASE, migration 1795601400).
- Install or update: `bash /root/acadiana-stack/pocketbase/install.sh` (first time: `curl -fsSL https://raw.githubusercontent.com/RobbieBott/Acadiana-mesh-site/main/infra/pocketbase/install.sh | bash`). It downloads this folder from GitHub, keeps the data and key, adds the compose service and Caddy block once, rebuilds and restarts. Previous compose/Caddyfile go to `/root/archive/pocketbase-<time>/`.

## Observer claims and directory management

Migration `1795601600_observer_claims.js` adds `managed_observers`, the privacy-limited `managed_observers_public` view, and `observer_claims`. The existing user account is reused. Claim submission verifies the exact observer ID against CoreScope, normalizes email, uses the signed-in account identity where available, and rate-limits claims. Admin approval creates or reuses the user, assigns the observer in a transaction, and emails the claimant. Only assigned managers or admins edit public metadata; only admins can change manager assignments. No observer hardware, MQTT credentials or analyzer account is modified. Deploy the backend migration before publishing the frontend when possible. Existing repeater data and claims are untouched.

## Owner emails and offline alerts

Deploy PocketBase before publishing Manage. Migration `1795601700_owner_mail.js` adds private send permissions, message history, delivery records, offline state and per-device pause dates.

- Add `DIRECTORY_SITE_OWNER_ID` to the existing PocketBase container environment file, using the PocketBase record ID of the confirmed directory administrator. Recreate PocketBase to pick up environment changes. The Site Owner can grant and revoke sending from **Manage → Permissions** for any verified directory account. Leave the ID unset to keep manual owner emails unavailable until configuration is complete.
- Manual notices use the existing PocketBase SMTP settings. Recipients come from verified accounts assigned as managers of directory records. An account tied to several selected devices receives one copy, and each message has a single private recipient. A change in the recipient list invalidates a preview. The send history shows SMTP acceptance and failures. An interrupted SMTP attempt is marked unconfirmed after an hour so it cannot be retried automatically and delivered twice.
- The hourly offline check defaults to log-only. Inspect `[owner alerts]` entries in PocketBase logs. When ready, set `OWNER_OFFLINE_ALERTS=send` and recreate PocketBase. Devices already flagged during the trial become eligible again after they report. The monitor checks repeater activity and observer status, needs recent Lafayette observer and repeater telemetry, and skips devices without a known report. It honors the per-device pause date and the Maintenance, Retired and Built Waiting For Install repeater statuses.
